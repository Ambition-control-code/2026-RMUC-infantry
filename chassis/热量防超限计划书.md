# 枪口热量防超限 —— 项目理解与实施计划

---

## 一、项目背景理解

### 1.1 系统架构

本项目是 **RoboMaster 机器人底盘控制系统**，运行于 STM32F407 微控制器，基于 FreeRTOS 和 CMake 构建。

核心控制链路：

```
遥控器/键盘 → CAN ID 0x301 → Data_C 控制数据
                                  ↓
              Chassis_control() 主循环 (1ms周期)
                  ↓
              chassis_mode() → FOLLOW / SPIN / STOP
                  ↓
              macnum_run() → 麦轮逆运动学解算 → 功率限制 → 射击
                  ↓
    Set_CHASSIS_Current()              Shoot_2006_SpeedLoop_SendCurrent()
    (底盘3508电机)                       (射击2006电机, CAN2 ID 0x1FF)
```

裁判系统数据链路：

```
裁判系统 UART → Umpire_UsartInit() → deal_data()
    ├── cmd 0x0201: 机器人状态（热量上限、功率上限等）
    └── cmd 0x0202: 实时功率/热量（枪口热量、底盘功率缓冲等）
                    ↓
              Robot_Para robot (全局结构体)
```

### 1.2 涉及的关键变量

| 变量 | 结构体字段 | 含义 | 来源 |
|------|-----------|------|------|
| `robot.shooter_heat0` | `Robot_Para.shooter_heat0` | 17mm 枪口实时热量 | 裁判系统 cmd 0x0202 |
| `robot.shooter_id1_17mm_cooling_limit` | `Robot_Para.shooter_id1_17mm_cooling_limit` | 枪口热量上限阈值 | 裁判系统 cmd 0x0201 |
| `Data_C.W` | `Data.W` (uint8_t) | 射击标志位 (0=停, 1=射) | CAN ID 0x301 bit0 |

### 1.3 当前问题

`Chassis_task.c` 第 180 行：

```c
Shoot_2006_SpeedLoop_SendCurrent(Data_C.W * 8000.0f);
```

射击电机转速固定为 **8000 rpm**，完全无视枪口热量状态。当 `shooter_heat0` 超过 `shooter_id1_17mm_cooling_limit` 后，裁判系统会对机器人施加惩罚（如扣血、降低输出功率等）。

### 1.4 热量机制说明

RoboMaster 裁判系统中，17mm 小弹丸发射枪口存在热量机制：

- 每发射一发弹丸，枪口热量 +10（由裁判系统统计，非底盘代码控制）
- 热量随时间按冷却速率 `shooter_id2_17mm_cooling_rate` 自然衰减
- 热量 ≥ 冷却上限时触发惩罚

## 二、需求分析

### 2.1 需求描述

> 当当前热量到达枪口热量的一半时，`Shoot_2006_SpeedLoop_SendCurrent` 里面的数值开始线性下降（最大值 8000）；当热量到达枪口热量的上限值后，数值降低到最小值 4000。

### 2.2 数学建模

设：
- `H` = 当前枪口热量 (`shooter_heat0`)
- `L` = 枪口热量上限 (`shooter_id1_17mm_cooling_limit`)
- `V` = 射击电机目标转速
- `r` = `H / L`（热量比例）

转速衰减曲线：

```
V(r)
│
8000 ┤────────────────●●●●●●●●●●●●●●●●
     │                  ●
     │                   ●
     │                    ●
6000 │                     ●  ← r=0.75 → 6000
     │                      ●
     │                       ●
4000 ┤────────────────────────●━━━━━━━━
     │                        │
     └────────────────────────┼────────── r
     0                      0.5        1.0
```

公式推导：

```
条件:  V(0.5) = 8000,  V(1.0) = 4000

线性差值:  V = V₀ + (V₁ - V₀) × (r - r₀) / (r₁ - r₀)
           V = 8000 + (4000 - 8000) × (r - 0.5) / (1.0 - 0.5)
           V = 8000 - 4000 × (r - 0.5) / 0.5
           V = 8000 - 8000 × (r - 0.5)
           V = 12000 - 8000 × r
```

验证：
- r = 0.50 → V = 12000 - 4000 = **8000** ✓
- r = 0.75 → V = 12000 - 6000 = **6000** ✓
- r = 1.00 → V = 12000 - 8000 = **4000** ✓

### 2.3 边界条件

| 场景 | 处理 |
|------|------|
| `limit == 0`（裁判系统未就绪）| 返回满速 8000，防止除零 |
| `W == 0`（未扣扳机）| 转速 = 0，不受热量影响 |
| `r < 0.5`（热量低于半值）| 满速 8000 |
| `0.5 ≤ r < 1.0` | 线性衰减 |
| `r ≥ 1.0`（热量超限）| 最低速 4000 |

## 三、实施计划

### 3.1 改动范围

**仅修改 1 个文件：** `Task/Chassis_task.c`

### 3.2 Step 1：新增宏定义

位置：`Chassis_task.c` 第 11 行之后（`SPIN_SPEED_RPM_MAX` 下方）

```c
#define SHOOT_SPEED_MAX  8000.0f
#define SHOOT_SPEED_MIN  4000.0f
```

### 3.3 Step 2：新增热量限制函数

位置：`macnum_run()` 函数之前（第 136 行之前）

```c
static float shooter_heat_speed_limit(void)
{
    uint16_t heat  = robot.shooter_heat0;
    uint16_t limit = robot.shooter_id1_17mm_cooling_limit;

    if (limit == 0) return SHOOT_SPEED_MAX;

    float ratio = (float)heat / (float)limit;

    if (ratio < 0.5f)       return SHOOT_SPEED_MAX;
    if (ratio >= 1.0f)      return SHOOT_SPEED_MIN;

    return 12000.0f - 8000.0f * ratio;
}
```

### 3.4 Step 3：修改 macnum_run() 中的调用

位置：`Chassis_task.c` 第 180 行

```c
// 修改前：
Shoot_2006_SpeedLoop_SendCurrent(Data_C.W * 8000.0f);

// 修改后：
Shoot_2006_SpeedLoop_SendCurrent(Data_C.W * shooter_heat_speed_limit());
```
